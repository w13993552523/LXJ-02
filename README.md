# 老乡鸡产品溯源系统交互原型

直接双击 `index.html` 打开。项目根目录的 `index.html` 和 `老乡鸡原型.html` 也会进入该原型。无需安装依赖或构建，Chrome、Edge、Safari 均可用于评审；浏览器文件模式限制可通过本地 HTTP 服务避免。

```bash
cd /Users/dingningdeair/Desktop/原型发布
python3 -m http.server 8765 --bind 127.0.0.1
```

访问 `http://127.0.0.1:8765/lxj/`。

所有原海底捞 Axure 页面、图片和脚本均保留；原入口另存为根目录 `海底捞参考入口.html`，`start.html` 仍可打开原项目。

本原型覆盖原料正向与逆向报告、菜品溯源报告、消费者报告、模板、环节、告警，以及产品、养殖、供应商、大仓、加工、配送、门店、食安和系统管理。列表支持全部字段横向滚动、固定标识与操作列、完整查询条件和分页。详情按 PRD 划分基本信息与子表，不以源数据编辑替代业务查询。

本地配置使用浏览器 localStorage 保存。“恢复演示数据”只清除当前原型的演示配置。列表不提供导出和列设置。附件预览支持本地 PDF 和图片；源附件未接入时明确提示。生产业务单据、源系统同步、权限鉴权、预警推送和任务执行不在静态 HTML 中实际执行。

客诉管理新增涉及金额（元）、处理反馈、日报日期、是否食安事件、食安事件责任方，并支持是/否筛选。通过“食安事件发送”人工判定并选择责任方，填写责任单位和判定说明后，可发送至对应责任系统或原客诉工单。发送仅在本机模拟，详情保留发送快照并拦截同内容同目标的重复发送；系统路由与操作人均为演示值，生产接入需使用真实工单标识、责任单位编码、权限身份与接口回执。旧浏览器记录缺少的人工判定保持待判定。

UI 统一采用主色 `#008042`、深色 `#005821`、浅色 `#ebf9f2`，以及规范中的 Danger / Warning / Info 颜色；普通文字 `#333333`。按钮圆角 4px，支持 default / plain / text 与 hover / active / disabled 状态。字段标签左对齐，菜单图标与文字作为整体排列，操作命名统一使用新增、查看、编辑、保存、取消、返回、搜索、重置与刷新。

逐页列表、筛选、子表和配置字段见 [字段与页面核对清单](字段与页面核对清单.md)。清单同时记录 PRD 未枚举的源字段、文档矛盾和验证范围，便于下一轮评审与接入。

源码：`assets/schema.js` 定义页面与字段；`assets/app.js` 实现路由、表单和交互；`assets/app.css` 定义统一 UI 组件与响应布局。

原料与菜品溯源报告以桌面更新版链路环节表为基础（原始定义为 8 个环节、28 张表、413 个展示字段），并已按最新要求调整央厨收货层级。详情保留各层关联，支持环节定位、原料展开、查询、分页和附件预览。字段编码、显示规则及源表行号见 [报告环节字段对照](报告环节字段对照.md)。`assets/report-schema.js` 保存该定义。

原料逆向报告位于原料正向报告下方，复用相同的列表与环节字段。每份报告从单条门店收货记录出发，只展示该收货单当前原料及关联环节；报告之间通过收货单、原料编码、批次和关联单据分别展示。

溯源模板总览的“关联溯源模板”打开菜品、原料、供应商的环节分支总览。根据最新启用模板展示环节，名称点击在新标签页打开相应模板；环节悬停显示编码、适用类型、版本和所属阶段，点击在新标签页打开对应环节详情。菜品未配置启用模板时显示“创建溯源模板”；菜品模板详情通过总览入口访问，不增加配置菜单。

模板详情中的环节以表格展示名称、版本、主表和子表数量。“关联原料 / 关联供应商”弹框支持编码精确查询与名称模糊查询；“环节导入”弹框支持关联对象和环节名称筛选、分页、多版本选择、当前页全选及跨页保留选择，取消不改变配置。新建和草稿可修改；已发布模板可打开弹框查看，结构变更通过新版本完成。

点击主表或子表数量，直接在当前页面打开字段结构弹框；子表弹框列出各层级表及上级表，可切换查看完整字段属性。结构采用更新版链路环节表及现有环节定义，源文件中的待补充字段保留提示。左侧导航在菜单切换、分组展开和页面重绘时保留滚动位置。

## 报告与告警配置更新（2026-10-15）

- 消费者报告列表支持单条关闭、本页全选、跨页多选和批量关闭。确认前列出所选报告；已关闭记录不再允许重复关闭，重新生成保留关闭状态，消费者预览停止展示。状态仅保存在当前浏览器。
- 告警配置详情分为配置基本信息、告警覆盖范围和配置详情。支持名称/说明字数限制、启停、菜品/原料/供应商与适配模板联动、三种告警类型、级别与告警动作联动、频率、用户组、时间范围及对应门店人员开关；保存校验必填项并支持回显。
- 正向报告用表格汇总同批次的多条环节记录，每行通过关联记录链接在当前页面打开弹框。弹框支持继续查看下级记录和返回上一级，查询条件按所选记录隔离。
- 正向、原料逆向、菜品报告均将央厨加工放在仓储入库前；央厨加工的“原料收货”替换为“仓储收货”，沿用仓储收货的完整字段及质检、供应商资质、批检附件关联层级。
- 各报告概要默认显示一行关键字段，完整概要点击展开；报告内统一使用仓储入库、仓储存储、仓储出库。

以上为静态 demo 交互，报告生成、真实消费者访问控制和预警发送仍需后端接入。


## 供应商与报告展示调整（2026-10-15）

供应商详情移除底部标签切换，基本信息与营业执照、关联生产商、供应商绩效、供应商附件、供货能力清单依次平铺；未定义接口字段的区块继续保留待接入提示。

原料正向及逆向报告列表增加“原料收货数量”。演示值按关联门店实收数量汇总：正向为多个收货记录之和，逆向对应当前单条收货记录；实际对接时须按源系统计量单位确认汇总口径。

正向报告的央厨加工展示一条生产订单，仓储收货、投料明细、检测和附件等全部在当前页面平铺。收货下的质检、资质及附件也直接展示，并通过“关联收货单”标识归属；各表独立查询和分页。其他环节及逆向、菜品报告保留关联弹框交互。

报告央厨加工环节已移除“批检附件表”，保留仓储收货关联的“批检附件”；“检测字段表”统一更名为“成品检测”。此调整适用于正向、原料逆向和菜品报告。
